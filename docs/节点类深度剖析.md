## 1. ShortUserRoleMemoryNode - 短期用户角色记忆节点

### 类的作用

1. **提取用户的角色特征和偏好信息**: 通过AI分析用户对话,提取职业、兴趣、专业领域等信息
2. **维护用户的短期记忆**: 实现个性化服务,记住用户的上下文
3. **根据历史对话记录,动态更新用户画像**: 避免信息过时
4. **为后续节点提供用户上下文信息**: 提升交互体验

### 设计理念

1. **用户画像构建**: 通过AI分析用户对话,提取角色特征
2. **记忆融合**: 智能融合历史记忆和当前提取结果
3. **置信度评估**: 通过置信度判断是否更新记忆
4. **渐进式更新**: 避免频繁更新,保持记忆稳定性
5. **结构化存储**: 使用JSON格式存储,便于查询和分析

### 在项目中的地位

- 这是深度研究系统的"个性化引擎"
- 位于工作流的最前端,为所有后续节点提供用户上下文
- 实现了AI系统的个性化能力
- 提升用户体验和交互质量

### 工作流程

```
1. 获取最近n轮用户提问
   ↓
2. 使用AI提取当前用户角色信息
   ↓
3. 与历史记忆进行智能融合
   ↓
4. 保存或更新短期记忆
   ↓
5. 将记忆传递给后续节点
```

### 为什么这么设计

1. **个性化需求**: 不同用户有不同的背景和需求,需要个性化服务
2. **上下文连续性**: 多轮对话需要记住用户信息,避免重复询问
3. **动态更新**: 用户角色可能随时间变化,需要动态调整
4. **质量保证**: 通过置信度评估,避免错误信息污染记忆

## 2. CoordinatorNode - 协调员节点

### 类的作用

1. **协调整个研究流程**: 决定是否启动深度研究或直接回答
2. **工具调用判断**: 通过检测工具调用,判断是否需要深度研究
3. **历史消息管理**: 维护对话历史,提供上下文
4. **流程路由**: 根据判断结果路由到不同的后续节点

### 设计理念

1. **智能路由**: 根据问题复杂度自动选择处理方式
2. **工具调用检测**: 通过检测tool_calls判断是否需要深度研究
3. **上下文管理**: 使用MessageWindowChatMemory维护对话历史
4. **容错设计**: 如果未触发工具调用,直接返回简单答案

### 在项目中的地位

- 这是深度研究系统的"流量控制器"和"智能路由器"
- 决定整个系统的执行路径
- 平衡简单问题和复杂问题的处理
- 提升系统响应效率

### 工作流程

```
1. 构建消息列表(包含短期记忆、历史消息、用户查询)
   ↓
2. 调用协调员AI代理
   ↓
3. 检测是否触发工具调用
   ↓
4. 如果触发工具调用 → 路由到查询重写节点(深度研究)
   ↓
5. 如果未触发工具调用 → 直接返回答案(简单回答)
```

### 为什么这么设计

1. **效率优先**: 简单问题不需要深度研究,直接回答更高效
2. **智能判断**: 使用AI判断问题复杂度,而非规则
3. **工具调用机制**: 通过tool_calls实现灵活的流程控制
4. **上下文连续性**: 维护对话历史,提供连贯的交互体验

### 核心代码解析

#### 1. 核心依赖

```java

@Override
public Map<String, Object> apply(OverAllState state) throws Exception {
    // 步骤1: 构建消息列表
    List<Message> messages = new ArrayList<>();
    TemplateUtil.addShortUserRoleMemory(messages, state);  // 添加短期记忆
    messages.add(TemplateUtil.getMessage("coordinator"));  // 添加系统提示
    
    // 添加历史消息
    if (enabledShortTermMemory) {
        List<Message> sessionHistoryMemory = messageWindowChatMemory.get(sessionId);
        messages.addAll(sessionHistoryMemory);
    }
    
    // 添加用户查询
    UserMessage userMessage = new UserMessage(StateUtil.getQuery(state));
    messages.add(userMessage);
    
    // 步骤2: 调用协调员AI代理
    ChatResponse response = coordinatorAgent.prompt().messages(messages).call().chatResponse();
    
    // 步骤3: 检测工具调用
    AssistantMessage assistantMessage = response.getResult().getOutput();
    if (assistantMessage.getToolCalls() != null && !assistantMessage.getToolCalls().isEmpty()) {
        // 触发工具调用 → 深度研究
        nextStep = "rewrite_multi_query";
        deepResearch = true;
    } else {
        // 未触发工具调用 → 简单回答
        updated.put("output", assistantMessage.getText());
    }
    
    updated.put("coordinator_next_node", nextStep);
    updated.put("deep_research", deepResearch);
    return updated;
}
```

## 3. RewriteAndMultiQueryNode - 查询重写和多查询节点

### 类的作用

1. **查询重写**: 将用户查询重写为更优化的形式
2. **多查询生成**: 生成多个相关查询,提高检索效果
3. **历史上下文压缩**: 压缩历史消息,优化查询质量
4. **查询数量控制**: 根据配置控制生成的查询数量

### 设计理念

1. **查询优化**: 通过AI重写,提高查询的准确性和完整性
2. **多角度检索**: 生成多个相关查询,从不同角度检索信息
3. **上下文感知**: 结合历史对话,理解用户真实意图
4. **数量控制**: 避免生成过多查询,影响性能

### 在项目中的地位

- 这是深度研究系统的"查询优化器"
- 提高信息检索的准确性和全面性
- 为后续节点提供高质量的查询
- 提升整体研究质量

### 工作流程

```
1. 获取用户查询
   ↓
2. 如果有历史消息,进行查询压缩
   ↓
3. 执行查询重写
   ↓
4. 执行多查询扩展
   ↓
5. 根据是否有用户上传文件,路由到不同节点
```

### 为什么这么设计

1. **查询质量**: 用户查询可能不完整或不准确,需要优化
2. **多角度检索**: 单一查询可能遗漏重要信息
3. **上下文理解**: 结合历史对话,理解用户真实意图
4. **性能平衡**: 查询数量需要平衡质量和性能

### 核心代码解析

#### 1. 核心依赖

```java
private final QueryTransformer queryTransformer;  // 查询转换器
private final ShortTermMemoryRepository shortTermMemoryRepository;  // 短期记忆存储库
private final ShortTermMemoryProperties shortTermMemoryProperties;  // 短期记忆配置
private final ChatClient.Builder rewriteAndMultiQueryAgentBuilder;  // 查询重写代理构建器
```

#### 2. 核心方法 apply()

```java
@Override
public Map<String, Object> apply(OverAllState state) throws Exception {
    // 步骤1: 获取用户查询
    String queryText = StateUtil.getQuery(state);
    Query query = Query.builder().text(queryText).build();
    
    // 步骤2: 如果有历史消息,进行查询压缩
    if (shortTermMemoryProperties.isEnabled()) {
        List<Message> recentUserMessages = shortTermMemoryRepository
            .getRecentUserMessages(StateUtil.getSessionId(state), null);
        if (!CollectionUtils.isEmpty(recentUserMessages)) {
            CompressionQueryTransformer compressionQueryTransformer = 
                CompressionQueryTransformer.builder()
                    .chatClientBuilder(rewriteAndMultiQueryAgentBuilder)
                    .build();
            Query queryWithHistory = Query.builder()
                .text(queryText)
                .history(recentUserMessages)
                .build();
            query = compressionQueryTransformer.transform(queryWithHistory);
        }
    }
    
    // 步骤3: 执行查询重写
    Query rewriteQuery = queryTransformer.transform(query);
    
    // 步骤4: 执行多查询扩展
    int optimizeQueryNum = StateUtil.getOptimizeQueryNum(state);
    optimizeQueryNum = Math.max(MinOptimizeQueryNum, 
        Math.min(MaxOptimizeQueryNum, optimizeQueryNum));
    
    QueryExpander queryExpander = MultiQueryExpander.builder()
        .chatClientBuilder(rewriteAndMultiQueryAgentBuilder)
        .includeOriginal(true)
        .numberOfQueries(optimizeQueryNum)
        .build();
    
    List<Query> multiQueries = queryExpander.expand(rewriteQuery);
    List<String> newQueries = multiQueries.stream()
        .map(Query::text)
        .collect(Collectors.toList());
    
    updated.put("optimize_queries", newQueries);
    
    // 步骤5: 根据是否有用户上传文件,路由到不同节点
    if (state.value("user_upload_file", false)) {
        nextStep = "user_file_rag";
    } else {
        nextStep = "background_investigator";
    }
    
    updated.put("rewrite_multi_query_next_node", nextStep);
    return updated;
}
```

### 设计理念

1. **多平台搜索**: 支持多个搜索平台,提高信息覆盖面
2. **智能选择**: 根据问题类型自动选择最合适的搜索平台
3. **初步调研**: 为深度研究提供基础信息
4. **上下文连续性**: 结合历史报告,提供连贯的上下文

### 在项目中的地位

- 这是深度研究系统的"信息收集器"
- 为深度研究提供初步信息
- 支持多智能体搜索
- 提升信息收集的广度和深度

### 工作流程

```
1. 遍历所有优化后的查询
   ↓
2. 对每个查询进行智能搜索平台选择
```

2. **智能选择**: 不同问题适合不同平台,需要智能选择

```java
@Override
public Map<String, Object> apply(OverAllState state) throws Exception {
    List<List<Map<String, String>>> resultsList = new ArrayList<>();
    List<String> queries = StateUtil.getOptimizeQueries(state);
    
    // 步骤1: 对每个查询进行搜索
    for (String query : queries) {
        // 使用统一的智能搜索选择方法
        SmartAgentUtil.SearchSelectionResult searchSelection = 
            smartAgentSelectionHelper.intelligentSearchSelection(state, query);
        
        // 使用支持工具调用的搜索方法
        List<Map<String, String>> results = searchInfoService.searchInfo(
            StateUtil.isSearchFilter(state),
            searchSelection.getSearchEnum(),
            query,
            searchSelection.getSearchPlatform()
        );
        resultsList.add(results);
    }
    
    resultMap.put("site_information", resultsList);
    
    // 步骤2: 生成背景调查报告
    List<String> backgroundResults = new ArrayList<>();
    for (int i = 0; i < resultsList.size(); i++) {
        List<Map<String, String>> searchResults = resultsList.get(i);
        String query = queries.get(i);
        
        // 构建消息列表
        List<Message> messageList = new ArrayList<>();
        TemplateUtil.addShortUserRoleMemory(messageList, state);
        
        // 添加搜索结果
        Message messages = new UserMessage(
            "搜索问题:" + query + "\n" + "以下是搜索结果：\n\n" + 
            searchResults.stream().map(r -> {
                return String.format("标题: %s\n权重: %s\n内容: %s\nurl: %s\n", 
                    r.get("title"), r.get("weight"), r.get("content"), r.get("url"));
            }).collect(Collectors.joining("\n\n"))
        );
        
        // 添加历史报告
        String sessionId = state.value("session_id", String.class).orElse("__default__");
        List<SessionHistory> reports = sessionContextService.getRecentReports(sessionId);
        Message lastReportMessage;
        if (reports != null && !reports.isEmpty()) {
            lastReportMessage = new AssistantMessage("这是用户前几次使用DeepResearch的报告：\r\n"
                + reports.stream().map(SessionHistory::toString).collect(Collectors.joining("\r\n\r\n")));
        } else {
            lastReportMessage = new AssistantMessage("这是用户的第一次询问，因此没有上下文。");
        }
        
        messageList.add(lastReportMessage);
        messageList.add(messages);
        
        // 生成背景调查报告
        String content = backgroundAgent.prompt().messages(messageList).call().content();
        backgroundResults.add(content);
    }
    
    resultMap.put("background_investigation_results", backgroundResults);
    
    // 步骤3: 根据是否启用深度研究,路由到不同节点
    String nextStep = "planner";
    if (!StateUtil.isDeepresearch(state)) {
        nextStep = "reporter";
    }
    resultMap.put("background_investigation_next_node", nextStep);
    
    return resultMap;
}
```

## 5. PlannerNode - 计划员节点

### 类的作用

1. **制定研究计划**: 将复杂任务分解为可执行的步骤
2. **任务分配**: 根据任务类型分配给不同的执行节点
3. **流式输出**: 使用流式输出,提供实时反馈
4. **上下文整合**: 整合背景调查、用户反馈等信息

### 设计理念

1. **任务分解**: 将复杂任务分解为可管理的小任务
2. **类型区分**: 区分研究任务(RESEARCH)和处理任务(PROCESSING)
3. **流式输出**: 提供实时反馈,提升用户体验
4. **上下文感知**: 结合所有可用信息,制定更准确的计划

### 在项目中的地位

- 这是深度研究系统的"任务规划器"
- 将用户查询转化为可执行的计划
- 为并行执行提供基础
- 是深度研究的核心环节

### 工作流程

```
1. 构建消息列表(包含短期记忆、系统提示、用户查询、背景调查、用户反馈、RAG内容)
   ↓
2. 调用计划员AI代理
   ↓
3. 流式输出研究计划
   ↓
4. 将计划保存到状态中
```

### 为什么这么设计

1. **任务管理**: 复杂任务需要分解,才能有效执行
2. **并行执行**: 计划支持并行执行,提高效率
3. **类型区分**: 不同类型任务需要不同的处理方式
4. **实时反馈**: 流式输出提供更好的用户体验

### 核心代码解析

#### 1. 核心依赖

```java
public Map<String, Object> apply(OverAllState state) throws Exception {

    String stepTitleKey = prefix + "_step_title";

        .startingState(state)
```

```java
@Override
public Map<String, Object> apply(OverAllState state) throws Exception {
    long currResearcher = 0;
    long currCoder = 0;
    
    Plan curPlan = StateUtil.getPlan(state);
    
    // 步骤1: 遍历计划中的所有步骤
    for (Plan.Step step : curPlan.getSteps()) {
        // 跳过不需要处理的步骤
        if (StringUtils.hasText(step.getExecutionRes()) || StringUtils.hasText(step.getExecutionStatus())) {
            continue;
        }
        
        Plan.StepType stepType = step.getStepType();
        
        switch (stepType) {
            case PROCESSING:
                // 处理任务: 需要等待所有研究任务完成
                if (areAllResearchStepsCompleted(curPlan)) {
                    step.setExecutionStatus(assignRole(stepType, currCoder));
                    currCoder = (currCoder + 1) % parallelNodeCount.get(ParallelEnum.CODER.getValue());
                }
                logger.info("Waiting for remaining research steps executed");
                break;
                
            case RESEARCH:
                // 研究任务: 直接分配
                step.setExecutionStatus(assignRole(stepType, currResearcher));
                currResearcher = (currResearcher + 1) % parallelNodeCount.get(ParallelEnum.RESEARCHER.getValue());
                break;
                
            default:
                logger.debug("Unhandled step type: {}", stepType);
        }
    }
    
    return Map.of();
}

/**
 * 分配角色
 */
private String assignRole(Plan.StepType type, long executorId) {
    String role = type == Plan.StepType.PROCESSING ? ParallelEnum.CODER.getValue()
            : ParallelEnum.RESEARCHER.getValue();
    return StateUtil.EXECUTION_STATUS_ASSIGNED_PREFIX + role + "_" + executorId;
}

/**
 * 检查所有研究步骤是否完成
 */
private boolean areAllResearchStepsCompleted(Plan plan) {
    if (CollectionUtils.isEmpty(plan.getSteps())) {
        return true;
    }
    
    return plan.getSteps()
        .stream()
        .filter(step -> step.getStepType() == Plan.StepType.RESEARCH)
        .allMatch(step -> step.getExecutionStatus().startsWith(StateUtil.EXECUTION_STATUS_COMPLETED_PREFIX)
                || step.getExecutionStatus().startsWith(StateUtil.EXECUTION_STATUS_ERROR_PREFIX));
}
```

```java
@Override
public Map<String, Object> apply(OverAllState state) throws Exception {
    String queryText = StateUtil.getQuery(state);
    
    Map<String, Object> options = new HashMap<>();
    state.value("session_id", String.class).ifPresent(v -> options.put("session_id", v));
    state.value("user_id", String.class).ifPresent(v -> options.put("user_id", v));
    options.put("query", queryText);
    
    List<Document> documents = new ArrayList<>();
    
    // 步骤1: 使用统一的RAG处理器或传统的策略模式
    if (hybridRagProcessor != null) {
        // 使用统一的RAG处理器,包含完整的前后处理逻辑
        Query query = new Query(queryText);
        documents = hybridRagProcessor.process(query, options);
    }
    else if (retrievalStrategies != null && fusionStrategy != null) {
        // 传统策略模式(向后兼容)
        List<List<Document>> allResults = new ArrayList<>();
        for (RetrievalStrategy strategy : retrievalStrategies) {
            allResults.add(strategy.retrieve(queryText, options));
        }
        documents = fusionStrategy.fuse(allResults);
    }
    
    // 步骤2: 构建上下文
    StringBuilder contextBuilder = new StringBuilder();
    for (Document doc : documents) {
        contextBuilder.append(doc.getText()).append("\n");
    }
    
    // 步骤3: 生成响应
    Flux<ChatResponse> streamResult = ragAgent.prompt()
        .messages(new UserMessage(contextBuilder.toString()))
        .user(queryText)
        .stream()
        .chatResponse()
        .timeout(Duration.ofSeconds(180))
        .retry(2);
    
    // 步骤4: 流式输出结果
    Flux<GraphResponse<StreamingOutput>> generatedContent = FluxConverter.builder()
        .startingNode("rag_llm_stream")
        .startingState(state)
        .mapResult(response -> Map.of("rag_content",
                Objects.requireNonNull(response.getResult().getOutput().getText())))
        .build(streamResult);
    
    Map<String, Object> updated = new HashMap<>();
    updated.put("rag_content", generatedContent);
    
    return updated;
}
```

```java
@Override
public Map<String, Object> apply(OverAllState state) throws Exception {
    String threadId = StateUtil.getThreadId(state);
    String sessionId = StateUtil.getSessionId(state);
    
    // 步骤1: 构建消息列表
    List<Message> messages = new ArrayList<>();
    TemplateUtil.addShortUserRoleMemory(messages, state);
    
    // 添加背景调查的信息
    List<String> backgroundInvestigationResults = state.value("background_investigation_results", (List<String>) null);
    for (String backgroundInvestigationResult : backgroundInvestigationResults) {
        if (StringUtils.hasText(backgroundInvestigationResult)) {
            messages.add(new UserMessage(backgroundInvestigationResult));
        }
    }
    
    // 添加深度研究信息
    if (state.value("enable_deepresearch", true)) {
        Plan currentPlan = StateUtil.getPlan(state);
        
        // 研究报告格式消息
        messages.add(new UserMessage(
                MessageFormat.format(RESEARCH_FORMAT, currentPlan.getTitle(), currentPlan.getThought())));
        
        // 添加研究组节点返回的信息
        List<String> researcherTeam = List.of(ParallelEnum.RESEARCHER.getValue(), ParallelEnum.CODER.getValue());
        for (String content : StateUtil.getParallelMessages(state, researcherTeam,
                StateUtil.getMaxStepNum(state))) {
            messages.add(new UserMessage(content));
        }
        
        // 添加专业知识库决策节点返回的信息
        if (state.value("use_professional_kb", false) && StringUtils.hasText(StateUtil.getRagContent(state))) {
            messages.add(new UserMessage(StateUtil.getRagContent(state)));
        }
    }
    
    // 步骤2: 流式输出报告
    String prefix = StreamNodePrefixEnum.REPORTER_LLM_STREAM.getPrefix();
    String stepTitleKey = prefix + "_step_title";
    state.registerKeyAndStrategy(stepTitleKey, new ReplaceStrategy());
    
    Map<String, Object> inputMap = new HashMap<>();
    inputMap.put(stepTitleKey, "[报告生成]");
    state.input(inputMap);
    
    Flux<ChatResponse> streamResult = reporterAgent.prompt().messages(messages).stream().chatResponse();
    
    Flux<GraphResponse<StreamingOutput>> generator = FluxConverter.builder()
        .startingNode(prefix)
        .startingState(state)
        .mapResult(response -> {
            String finalReport = Objects.requireNonNull(response.getResult().getOutput().getText());
            try {
                // 保存报告到会话历史
                GraphId graphId = new GraphId(sessionId, threadId);
                String userQuery = state.value("query", String.class).orElse("UNKNOWN");
                if (shortTermMemoryProperties.isEnabled()) {
                    messageWindowChatMemory.add(sessionId, new AssistantMessage(finalReport));
                }
                sessionContextService.addSessionHistory(graphId,
                        SessionHistory.builder().graphId(graphId).userQuery(userQuery).report(finalReport).build());
                logger.info("Report saved successfully, Thread ID: {}", threadId);
            }
            catch (Exception e) {
                logger.error("Failed to save report, Thread ID: {}", threadId, e);
            }
            return Map.of("final_report", finalReport, "thread_id", threadId);
        })
        .buildWithChatResponse(streamResult);
    
    Map<String, Object> resultMap = new HashMap<>();
    resultMap.put("final_report", generator);
    resultMap.put("thread_id", threadId);
    
    return resultMap;
}
```

## 总结

深度研究系统的14个节点构成了一个完整的多智能体协作工作流:

1. **前端节点** (1-3): ShortUserRoleMemoryNode、CoordinatorNode、RewriteAndMultiQueryNode
   - 负责用户理解、流程路由、查询优化

2. **信息收集节点** (4-5): BackgroundInvestigationNode、PlannerNode
   - 负责初步信息收集、任务规划

3. **流程控制节点** (6-8): InformationNode、HumanFeedbackNode、ResearchTeamNode
   - 负责计划验证、人工确认、任务协调

4. **执行节点** (9-11): ParallelExecutorNode、ProfessionalKbDecisionNode、RagNode
   - 负责并行调度、知识库选择、RAG检索

5. **核心执行节点** (13-14): ResearcherNode、CoderNode
   - 负责研究任务、编程任务

6. **后端节点** (12): ReporterNode
   - 负责报告生成

每个节点都有明确的职责和设计理念,共同构成了一个高效、智能的深度研究系统。
