# DeepResearch项目完整分析报告

## 文档说明

本文档提供了DeepResearch项目的系统性分析，包括项目目标、系统架构、模块划分、执行流程、技术亮点和关键代码文件。本文档将作为后续讲解项目的基准文档。

---

## 1. 项目整体目标和解决的问题

### 核心目标

基于Spring AI Alibaba Graph框架构建智能深度研究平台，实现自动化、多源集成的AI驱动研究能力。

### 解决的核心问题

- **复杂研究流程自动化**：将多步骤、多来源的研究任务自动化执行
- **多源信息整合**：统一多个搜索引擎和知识库的检索能力
- **智能任务分解与执行**：通过AI自动规划研究路径并分步执行
- **实时人机协作**：支持人工干预和反馈机制
- **知识增强生成**：结合RAG技术提供专业领域知识支持

│   ├── ParallelExecutorNode - 并行执行协调节点
│   └── ResearchTeamNode - 研究组协调节点
├── 知识增强节点
│   ├── ProfessionalKbDecisionNode - 专业知识库决策
│   ├── RagNode - RAG检索节点
│   └── ShortUserRoleMemoryNode - 用户角色记忆
├── 交互节点
│   └── HumanFeedbackNode - 人工反馈节点
└── 输出节点
    └── ReporterNode - 报告生成节点

## 4. 整体执行流程（从用户输入到最终输出）

### 4.1 完整执行流程

```
┌─────────────────────────────────────────────────────────────────┐
│                        用户请求流程                               │
└─────────────────────────────────────────────────────────────────┘

1. 用户提交查询
   ↓
2. ChatController接收请求 (/chat/stream)
   ├─ 生成唯一threadId (sessionId + 计数)
   ├─ 初始化OverAllState
   └─ 创建RunnableConfig
   ↓
3. 执行图流程 (StateGraph)
   ├─ START节点初始化
   │
   ├─ CoordinatorNode (协调器)
   │   ├─ 分析用户查询
   │   ├─ 检查历史记忆
   │   ├─ 判断是否需要工具调用
   │   └─ 决定下一步：
   │       ├─ 简单查询 → END节点直接回答
   │       └─ 复杂查询 → rewrite_multi_query
   │
   ├─ RewriteAndMultiQueryNode (查询重写)
   │   ├─ 重写原始查询
   │   └─ 生成多个搜索查询
   │
   ├─ BackgroundInvestigationNode (背景调查)
   │   ├─ 快速背景信息收集
   │   └─ 提供上下文信息
   │
   ├─ PlannerNode (任务规划)
   │   ├─ 基于背景信息制定研究计划
   │   ├─ 生成结构化Plan对象
   │   └─ 定义研究步骤(steps)
   │
   ├─ ResearchTeamNode (研究组协调)
   │   ├─ 检查计划执行状态
   │   └─ 循环直到所有步骤完成
   │
   ├─ ParallelExecutorNode (并行执行)
   │   ├─ 并行调度ResearcherNode和CoderNode
   │   ├─ 每个节点执行独立的搜索和分析
   │   └─ 收集所有执行结果
   │
   ├─ ResearcherNode (研究者)
   │   ├─ 执行多源搜索
   │   ├─ 整合搜索结果
   │   ├─ 生成深度分析内容
   │   └─ 更新步骤执行状态
   │
   ├─ CoderNode (编程者)
   │   ├─ Python代码生成
   │   ├─ Docker容器执行
   │   ├─ 数据分析计算
   │   └─ 返回计算结果
   │
   ├─ ProfessionalKbDecisionNode (专业知识库决策)
   │   ├─ 评估是否需要专业知识库
   │   └─ 决定检索策略
   │
   ├─ RagNode (RAG检索)
   │   ├─ 执行向量检索
   │   ├─ 融合多源结果
   │   └─ 返回相关文档片段
   │
   ├─ HumanFeedbackNode (人工反馈) [可选]
   │   ├─ 检查是否需要人工确认
   │   ├─ 暂停流程等待反馈
   │   └─ 根据反馈调整执行
   │
   └─ ReporterNode (报告生成)
       ├─ 汇总所有研究内容
       ├─ 生成最终报告
       ├─ 流式输出结果
       └─ 保存到会话历史
   ↓
4. 流式输出给前端 (SSE)
   ├─ 实时推送节点输出
   ├─ 显示执行进度
   └─ 显示最终报告
   ↓
5. 前端展示
   └─ 渲染Markdown报告
```

## 5. 项目核心技术亮点

### 5.1 图驱动执行框架

基于Spring AI Alibaba Graph的状态机设计，支持：
- 复杂的分支、循环、并行执行模式
- 状态快照和断点续传机制
- 可视化的状态流转

### 5.2 智能Agent路由系统

- 根据查询类型自动选择最优Agent
- 支持通用研究、学术研究、旅游生活、百科知识、数据分析等场景
- 多搜索引擎智能映射和负载均衡

### 5.3 混合RAG架构

- RRF（Reciprocal Rank Fusion）融合策略
- HyDe（Hypothetical Document Embeddings）查询变换
- 多源检索策略：向量检索、关键词检索、专业API检索
- 支持Elasticsearch和Simple向量存储

### 5.4 响应式流式处理

- 基于Reactor的Flux流式处理
- SSE（Server-Sent Events）实时推送
- 非阻塞的异步任务调度
- 完善的错误处理和任务取消机制

### 5.5 智能记忆系统

- 短期记忆：会话记忆（MessageWindowChatMemory）
- 用户角色记忆：动态提取用户偏好
- 记忆更新策略：相似度阈值控制
- 持久化支持：Redis和内存存储

### 5.6 人工在环（Human-in-the-loop）

- 中断点配置：支持在特定节点暂停
- 人工反馈机制：支持修改和优化执行路径
- 交互式决策：用户可干预研究过程

### 5.7 多源搜索引擎集成

- 统一的搜索接口抽象
- 支持Tavily、Jina、百度、SerpAPI、阿里云AI搜索
- 搜索结果聚合和去重

### 5.8 安全的代码执行

- Docker容器隔离
- Python沙箱环境
- 临时容器创建和销毁

### 5.9 可观测性和监控

- OpenTelemetry集成
- Langfuse分布式追踪
- 完整的执行链路记录

### 5.10 模板化和配置化

- 模板系统统一管理Prompt
- 灵活的配置机制
- 支持多种部署方式
