可能存在的问题：

**场景1：正常完成**
- 任务正常执行完成
- 触发 `doOnComplete`

- ✅ 任务从Map中移除

注意到代码中存在一个潜在的资源管理问题。在异常和取消场景下，任务可能无法正确从Map中移除，这可能导致内存泄漏或资源未正确释放。需要在错误处理和取消逻辑中添加Map清理机制。

关键风险点包括异常处理、任务取消和并发场景下的资源管理。通过在 `doOnError` 中添加清理逻辑，可以有效防止内存泄漏和资源残留。同时，使用 `remove` 方法可以避免潜在的并发竞争问题。

# 任务Map中残留任务的可能性分析

## 一、问题答案

**是的，完全有可能！** 在当前设计下，存在**多种场景**会导致任务在线程池中已经完成，但Map中仍然存在该任务。

---

## 二、问题场景分析

### 场景1：发生异常时未清理Map ❌

**当前代码**：
```java
.doOnError(e -> {
    logger.error("Error in stream processing", e);
    sink.tryEmitNext(
        ServerSentEvent.builder(String.format(TASK_STOPPED_MESSAGE_TEMPLATE, graphIdStr, "服务异常"))
            .build());
    sink.tryEmitError(e);
    // ❌ 缺少：graphTaskFutureMap.remove(graphId);
})
```

**问题**：
- 当流处理过程中发生异常时，触发 `doOnError`
- 发送错误消息给前端
- **但是没有从Map中移除任务**
- 导致Map中残留已失败的任务

**实际执行流程**：
```
1. 任务开始执行
2. 发生异常（如网络超时、JSON解析错误等）
3. 触发 doOnError
4. 发送错误消息给前端
5. ❌ 任务仍在Map中
6. ❌ 内存泄漏
```

---

### 场景2：任务被取消时未清理Map ❌

**当前代码**：
```java
public boolean stopGraph(GraphId graphId) {
    Future<?> future = this.graphTaskFutureMap.remove(graphId);  // ✅ 这里移除了
    if (future == null) {
        return false;
    }
    if (future.isDone()) {
        return true;
    }
    return future.cancel(true);  // ❌ 但任务内部可能没有清理
}
```

**问题**：
- 调用 `stopGraph` 时，从Map中移除了Future
- 调用 `future.cancel(true)` 中断任务
- 但是任务内部的 `doOnComplete` 和 `doOnError` **可能都不会被触发**
- 如果任务在取消前已经将Future重新put回Map（虽然当前代码没有），就会残留

**更严重的问题**：
```java
// 如果在 stopGraph 之前，任务已经完成但还未触发 doOnComplete
// 此时 stopGraph 被调用
Future<?> future = this.graphTaskFutureMap.remove(graphId);  // 移除了
future.cancel(true);  // 取消一个已完成的任务

// 稍后，doOnComplete 被触发
.doOnComplete(() -> {
    graphTaskFutureMap.remove(graphId);  // ❌ 尝试移除一个不存在的任务
})
```

### 场景3：并发竞争条件 ⚠️

**当前代码**：
```java
Future<?> future = executor.submit(() -> {
    generator.doOnNext(...)
             .doOnComplete(() -> {
                 graphTaskFutureMap.remove(graphId);  // 线程A：工作线程
             })
             .subscribe();

Future<?> oldFuture = graphTaskFutureMap.put(graphId, future);  // 线程B：主线程
```

**可能的竞争**：
```
时间线 →

工作线程（A）              主线程（B）
    |                          |
    |-- 任务完成               |
    |-- doOnComplete()         |
    |   .remove(graphId) ----->|  (移除任务)
    |                          |
    |                          |-- .put(graphId, future)
    |                          |  (重新放入)
    |                          |
    |                          |-- 任务已从Map中消失
```

**虽然当前代码不太可能出现这个问题**（因为 `put` 在 `submit` 之后立即执行），但在复杂的并发场景下仍需注意。

## 四、解决方案

### 方案1：在所有退出点清理Map（推荐）

```java
public void processStream(GraphId graphId, Flux<NodeOutput> generator, 
                         Sinks.Many<ServerSentEvent<String>> sink) {
    final String graphIdStr = this.safeObjectToJson(graphId);
    Future<?> future = executor.submit(() -> {
        try {
            generator.doOnNext(output -> {
                // ... 处理逻辑
            }).doOnComplete(() -> {
                logger.info("Stream processing completed.");
                sink.tryEmitComplete();
            }).doOnError(e -> {
                logger.error("Error in stream processing", e);
                sink.tryEmitNext(
                    ServerSentEvent.builder(String.format(TASK_STOPPED_MESSAGE_TEMPLATE, graphIdStr, "服务异常"))
                        .build());
                sink.tryEmitError(e);
            }).subscribe();
        } finally {
            // ✅ 确保在任何情况下都清理Map
            graphTaskFutureMap.remove(graphId);
            logger.debug("Task {} removed from map", graphId);
        }
    });
    
    graphTaskFutureMap.put(graphId, future);
}
```

**优点**：
- 使用 `finally` 块确保无论如何都会清理
- 简单可靠
- 覆盖所有异常场景

### 方案4：添加定时清理任务（防御性措施）

```java
// 定时清理已完成但仍在Map中的任务
@Scheduled(fixedDelay = 60000)  // 每分钟执行一次
public void cleanupCompletedTasks() {
    Iterator<Map.Entry<GraphId, Future<?>>> iterator = graphTaskFutureMap.entrySet().iterator();
    while (iterator.hasNext()) {
        Map.Entry<GraphId, Future<?>> entry = iterator.next();
        Future<?> future = entry.getValue();
        if (future.isDone()) {
            iterator.remove();
            logger.info("Cleaned up completed task: {}", entry.getKey());
        }
    }
}
```

**优点**：
- 作为防御性措施
- 自动清理残留任务
- 不影响主逻辑

**缺点**：
- 有延迟（最多1分钟）
- 增加系统复杂度

## 六、总结

### 问题确认

✅ **确实存在任务已完成但Map中仍残留的问题**

### 主要原因

1. ❌ `doOnError` 中缺少清理逻辑
2. ❌ 异常处理分支中缺少清理逻辑
3. ⚠️ 任务取消时的清理时机不确定

### 推荐解决方案

1. **立即修复**：在 `doOnError` 中添加 `graphTaskFutureMap.remove(graphId)`
2. **长期优化**：使用 `try-finally` 包装整个流处理
3. **防御措施**：添加定时清理任务

### 关键原则

**"每个任务进入Map时，都要确保有对应的退出清理逻辑"**

这是资源管理的基本原则，可以避免内存泄漏和状态不一致问题。
